## Executive summary

The biggest parity wins are **cross-cutting**, not per-surface. In order of impact:

1. **Body font is monospace by default** (`main.css:296-305`) while opencode uses `ui-sans-serif, system-ui…` at 14px (`theme.css:~440` font stack). This single line touches every surface and is the dominant visual delta. **Fix = S, P0**.
2. **Token ladder is 3-step, opencode's is 7-step**. We have `--color-surface`, `--color-surface-alt`, `--color-surface-raised`; opencode has `--surface-base/weak/weaker/strong/raised-base/raised-strong/raised-stronger/float`. Tool-call CSS already imports the opencode names (`main.css:54-120`) but they're only defined for root+dark — tinted themes (sage/sand/teal/sky) fall back. **Fix = M, P0**.
3. **Composer is a two-part container** in our app (outer rounded box + bottom toolbar with `border-t`, `ChannelComposer.tsx:312-453`; `ComposerBottomBar.tsx:96`). Opencode's is **one visually-continuous rounded surface** with an absolutely-positioned send button and a `DockTray attach="top"` for model/agent (`prompt-input.tsx` shows `DockShellForm`+`DockTray` pattern). **Fix = M, P1**.
4. **Titlebar is a pure app-brand header** in our app (`App.tsx:113-154`) — no session-aware portal slots. Opencode's titlebar exposes `#opencode-titlebar-left/center/right` Portal mounts that `SessionHeader` injects into (`session-header.tsx` portals search box to `center`, toolbar to `right`). Our `ChannelHeader` re-implements all of it inside a second sub-header (`ChannelHeader.tsx:143-524`), producing a **double-header**. **Fix = L, P1**.
5. **Sidebar project rail uses colored initial tiles** (`ProjectRail.tsx:38-54, 78-83`) with bespoke ring-offset glow on select. Opencode uses token-driven `getAvatarColors()` avatars, `size-8 rounded`, with `size-1.5 rounded-full` unseen/error dot absolute top-right (`sidebar-items.tsx` `ProjectIcon`). **Fix = S, P2**.
6. **No shadow/focus ring token system**. We reach for `ring-1 ring-[var(--color-agent)]/20` etc. ad hoc. Opencode defines `--shadow-xs-border`, `--shadow-xs-border-focus`, `--shadow-xs-border-select`, `--shadow-xs-border-critical-focus` (`theme.css:~490-540`) and every interactive component uses them. **Fix = M, P0**.
7. **Emoji provider icons** in `ProviderAuthSection.tsx:240-261` (🅰️🤖🔮💎📦). Opencode has `packages/ui/src/components/provider-icon.tsx` with real SVG logos. Low-effort quality win. **Fix = S, P1**.

**Top-10 LOC of impact**: items 1, 2, and 6 together replace hundreds of ad-hoc class literals across the app with token-driven styling — these three alone get us ~60% of the visual parity we need without touching component structure.

### Cross-cutting gaps

#### 9.1 Body font — monospace vs sans `S / P0`

Our default (`main.css:296-305`): `'SF Mono','Fira Code','JetBrains Mono','Consolas','Monaco','Courier New',monospace` at 13px. Opencode: `ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont, …` at 14px. Mono should be reserved for code blocks, inline `<code>`, and the tool-trigger row. Fix in one file. **Highest ROI single change in this report.**

#### 9.2 Semantic color tokens — incomplete migration `M / P0`

Ad-hoc tailwind color classes (`emerald-500`, `green-500`, `amber-300`, `purple-400`, `sky-500`, `red-500`) appear in: `MessageItem.tsx:207-260, 518`, `ProviderAuthSection.tsx:123,139-151`, `ChannelHeader.tsx:95-96`, `App.tsx` (`color-agent`, `color-user`), `ProjectRail.tsx:40-47`. Define the full opencode ladder (`--surface-success/warning/critical/info`, `--text-on-*`, `--icon-agent-*`) at root + dark + all 4 tinted themes, then search-and-replace. Existing `--color-agent` and `--color-user` can stay as aliases.

#### 9.3 Typography scale classes `S / P1`

Introduce `.text-13-regular`, `.text-13-medium`, `.text-14-regular`, `.text-14-medium`, `.text-20-medium` utilities in `main.css` mapping to opencode's family + size + line-height + weight. Replaces dozens of `text-[11px]`, `text-[13px]`, `text-xs font-medium` ad-hoc classes.

#### 9.4 Shadow + focus ring token system `M / P0`

Currently `ring-1 ring-[var(--color-agent)]/20` and `shadow-sm` are everywhere. Define:

- `--shadow-xs`: `0 1px 2px rgba(0,0,0,0.04)`
- `--shadow-xs-border`: `0 0 0 1px var(--border-weak-base), var(--shadow-xs)`
- `--shadow-xs-border-focus`: `0 0 0 1px var(--border-interactive), 0 0 0 3px var(--border-interactive)/20`
- `--shadow-xs-border-select`: `0 0 0 1px var(--border-weak-selected)`
- `--shadow-xs-border-critical-focus`: same pattern with critical token.
  Then ship a Tailwind plugin or custom utilities for `shadow-xs-border-focus` etc. Unblocks gaps 1.4, 2.8, 4.6, 7.3.

#### 9.5 Radius scale `S / P2`

Opencode: xs=2, sm=4, md=6, lg=8, xl=10 (`main.css:85-88` already matches!). Usage inconsistent: `ChannelComposer.tsx:314` uses `rounded-[12px]`, `NewSessionInput.tsx:287` uses `rounded-lg` (8). Standardize to tokens: composer = `xl` (12), button = `md` (6), chip = `sm` (4), avatar = `md`.

#### 9.6 Icons `M / P1`

Recommendation: centralize on `lucide-react` for generic icons, and ship a small `<ProviderIcon />` React component with SVG paths for ~12 providers (see 5.1, 8.1). Kill all emoji icons.

#### 9.7 Motion `S / P2`

## Risk notes

- **None of the top-15 require touching the ConversationEvent reducer or session-graph store.** All are pure presentational changes (CSS + JSX class swaps + small new React components). No `STATE CHANGE` flags.
- **Token rename risk**: changing `--color-surface` etc. would break the tool-call parity already shipped (references in `main.css:819-1300`). Mitigation: keep legacy names as _aliases_ to the new opencode-named tokens; do not delete.
- **Electron drag region**: `App.tsx:115` `titlebar-drag` class must remain on whatever element houses traffic lights on macOS. If gap 1.1 moves `ChannelHeader` contents into the titlebar, take care that the new injected elements use `-webkit-app-region: no-drag` (the opencode `titlebar-no-drag` equivalent is present on `App.tsx:130`).
- **ProgressCircle component (quick win #6)**: SVG implementation is straightforward but must handle 0/undefined percentage gracefully to avoid `NaN` in `stroke-dasharray`. 30 min of care.
- **Tinted themes**: gap 9.2 will expand `main.css` by ~150-200 lines because all 4 tinted themes need `--surface-success/warning/critical/info` + `--text-on-*` + `--icon-agent-*` definitions. Defer any gap that requires a new semantic token until those theme definitions exist, otherwise the tinted themes will regress.
- **contenteditable composer (gap 4.2)**: Flagged **L/P1 but don't do it yet**. Very high blast radius (keyboard events, paste, IME, mention pills, undo stack). Defer until the rest of parity is shipped; user never asked for mentions specifically.
- **Hover-aim peek (gap 2.3)**: requires either `@floating-ui` aim library or custom Pointer math. Defer to P2.
- **Lucide icon sizing**: our existing lucide imports are fine, but verify stroke-width parity with opencode's SVG icons (they use 1.5-1.6 stroke; lucide defaults to 2). Set `<Icon strokeWidth={1.5}>` globally or via wrapper.
